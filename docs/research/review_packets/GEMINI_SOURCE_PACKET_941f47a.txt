## 1. Evidence and causal boundaries

Inspected: the pasted proposal/review, committed contract at `a936dec5`, its
workplan, `backend/coinbase_ws.py`, and primary Coinbase documentation on
2026-10-27. No live packets or database contents were sampled in this review.
The workplan's 23s median / 110s maximum BTC snapshot gaps are prior bounded
inventory findings, not new measurements. They establish inadequate exact
sub-minute coverage in that store. They do not establish a Nyquist floor or
a natural 30-second market timescale. Claims about typical 10-45s sweeps,
1-2m replenishment, trade counts and 407 currently active products remain
unverified hypotheses or sizing assumptions.

Keep the following timestamps separate:

| Field | Meaning and use |
|---|---|
| `exchange_event_ts_ms` | Message `time`; trade event time on match records. A ticker timestamp does not timestamp every intervening quote change. |
| `server_receipt_ts_ms` | UTC wall-clock receipt time, e.g. `time.time_ns() // 1_000_000`; determines when an input became available. This clock is not monotonic. |
| `receipt_monotonic_ns`, `connection_id`, `receipt_seq` | Local elapsed-time/ordering evidence, including clock jumps and reconnects; monotonic values are not UTC or comparable across restarts. |
| `feature_cutoff_ts_ms` (`t0`) | Frozen scoring cutoff; only observations received at or before this instant may contribute. |
| `board_publish_ts_ms` (`t_alert`) | Actual server publication of the scored row; separate from computation start and browser display. |

Use completed 5s buckets ending at `b = floor(t0 / 5000) * 5000`. Inputs are
the six buckets `[b-30s, b)` and 36 buckets `[b-180s, b)`, with endpoint and
observation-age metadata. At non-aligned publication times, record `t0-b`;
do not call the inputs exact windows ending at publication. Forward outcomes
start strictly after `t_alert`, for 5m and 15m. Never use messages received
after `t0` merely because their exchange timestamps precede it.
Invalidate buckets affected by a backward wall-clock jump; receipt ordering
must also agree with the connection's monotonic clock and sequence.

Only use closed baseline candles whose end time and first availability time
are both at or before `t0`. Define the 60m volatility baseline from prior
closed 1m log returns, with a declared 0.0015 per-minute floor. Record the
floor flag, sample count and source timestamp; this is a candidate scale,
not a distributional guarantee. Beta must also be available at `t0`; a
default of 1.0 requires an explicit fallback flag.

**Onset, future retention, peak time and fraction of move consumed are
evaluation labels only.** The proposal's "without later retracing" test
necessarily reads future prices. None of these fields may feed a live
feature, stage, eligibility gate, fitted-input column or universe selection.
The evaluator must freeze a direction-symmetric onset algorithm, search

## 3. Five-second storage, reconstruction and freshness

**Choose sparse persistence and reconstruct logical empty buckets on read.**
Write a `micro_bars_5s` row when a unique match or a ticker observation is
received, including unchanged quote observations needed to retain freshness.
Use receipt-time buckets `[start, start+5000)`. Alongside the sparse table,
retain subscription membership and feed-health intervals so an absent row
can be distinguished from collector downtime. No reconstruction across an
unverified interval is permitted.

Minimum row/provenance fields:

- Canonical `product_id`, `bucket_start_ts_ms`, first/last receipt times,
  last exchange event time per source, connection/receipt ordering fields,
  and first/last match trade IDs with coverage status.
- Observed midpoint OHLC, last trade price, last observed bid/ask and sizes,
  spread, quote observation time, last live-match receipt time, and
  `seconds_since_last_trade` / `seconds_since_last_quote` separately.
- `trade_count`, `quote_vol_usd`, `taker_buy_usd`, `taker_sell_usd`, all from
  unique live match executions. Unknown sides require an unknown-side amount
  and unavailable F2; do not force a two-way split.
- `price_source` (`mid`, `last_trade_fallback`, `unavailable`), fallback
  reason, observed/carried flags, quote validity, endpoint ages, feature
  coverage and whether any source or connection gap affects the window.

Within a continuously verified healthy interval, reconstruct a missing 5s
row with zero observed trades/volume and carry the prior quote state and its
**original** observation timestamp. Do not create a new trade, fresh quote
or observed OHLC path. Carried midpoint values describe last-known state.
Missing rows during downtime are unknown, not zero-volume observations.
Completeness verdicts can arrive later; retain the verdict known at `t0`
and any later audit verdict separately. Never rewrite a published feature.

For primary 30s/3m midpoint features, require valid positive non-crossed BBO
at each return endpoint, quote age <=10s at each endpoint, continuous feed
coverage across the window, and at least one unique live match in it. Record
the true endpoint ages. This replaces the loose proposed +/-10s reference
search. Midpoint-path features also require valid quote coverage throughout
their calculation. An `IGNITING` candidate additionally needs >=5 matches
in its 30s window; a volume multiple alone cannot let one print pass.
These fixed candidate gates may exclude thin coins; report that coverage.

If only a last trade is available, retain it with `last_trade_fallback` on
that row and propagate the flag to affected features. Exclude such rows
from the primary midpoint acceleration/decay cohort and report a separate
fallback cohort. Do not mix sources or treat a missing spread as zero.
Ticker-derived OBI averages are time averages of last-observed BBO state,
with stale durations marked unavailable; six endpoint snapshots do not
establish a continuously observed book. A future L2 feed would be a separate
versioned source change.

Late WS matches belong to their actual receipt bucket. Recovered REST trades
need `recovery_receipt_ts_ms` and exchange-time attribution in a separate
reconciliation record. They may repair an offline coverage audit, but must
not retroactively enter an earlier live bucket or inflate the recovery
instant's trading pace. Windows with unresolved earlier gaps stay ineligible
for complete-flow features at the original cutoff.

## 4. Correct the smoothing math and keep feature hypotheses separate

Keep raw 30s and 3m percentage-return columns available for interpretation.
For smoothed candidate inputs use an **unnormalized decayed sum of log-return
increments**, per product, with fixed half-lives `h = 30s` and `h = 180s`:

```text
delta = 5 seconds; q_h = 2 ** (-delta / h)
x_i,j = log(mid_i,j / mid_i,j-1) - beta_i * log(mid_BTC,j / mid_BTC,j-1)
S_i,h,j = q_h * S_i,h,j-1 + x_i,j
decayed_move_sigma_i,h,j = S_i,h,j / sigma_i,1m(t0)
```

Use synchronized valid midpoint endpoints and beta known before the
increment; unavailable BTC/beta provenance makes the residual unavailable.
The denominator is that coin's causal one-minute baseline volatility, with
the declared floor. This is a scaled move, not a calibrated Gaussian z-score
or a claim of equal variance across half-lives. Any feature scaling for a
fit is learned on discovery only and frozen before validation.

There is **no leading `lambda = 1-q` multiplier and no unit-sum
normalization**. Those produce a weighted average increment rather than a
decayed cumulative move. For an isolated 0.02 log-return impulse, its weight
at age 30s with a 30s half-life is 0.500, at 31s it is 0.48858, and at 35s
it is 0.44545. The contribution is respectively 0.01000, 0.00977 and 0.00891
in log-return units. The 31s value describes continuous exponential decay;
closed-bucket observations still update every 5s.

Maintain the state independently per coin and half-life. Warm up for at
least ten slow half-lives (30m) plus the required baseline history. A true
no-trade bucket with valid observed price state can contribute a zero
increment; an unknown/stale interval cannot. Reset or mark state warming
after such a gap and satisfy warmup again. Never bridge a missing interval
with a newly received multi-minute return presented as a 5s impulse.

F1-F5 remain candidate mechanisms; their independence and usefulness are
unproven. The source/interpretation corrections apply as follows:

| Feature | Corrected dependency / interpretation |
|---|---|
| F1 acceleration | Midpoint returns over non-overlapping 30s and preceding 150s, normalized by per-coin baseline; flagged trade-price fallbacks are excluded from the primary cohort. |
| F2 signed participation | `TakerImb * log(1 + PaceRatio)`, gated on >=5 unique matches. Imbalance uses match-derived buy/sell USD; pace uses prior completed matched-volume windows. Historical 1m candle volume is not measured 30s taker flow. |
| F3 book pressure | Valid observed ticker BBO/sizes and spread, with observation ages and time weighting; no claim to full-book coverage. Optional perp data cannot substitute for missing required spot features. |
| F4 compression | Prior closed, already available candle history; require >=10 traded candles in the prior 15 completed minutes. Missing or late-fetched candles cannot become earlier features. |
| F5 market residual | Coin and BTC endpoints at the same causal cutoff, with beta provenance; a beta fallback remains visible. |

Freeze exact formulas, minimum baseline sample counts, missing-feature
policy and model inputs in the implementation contract. Do not automatically
add both decayed sums as extra fitted predictors beyond the declared five,
or choose between smooth and boxcar variants using test outcomes.

## 5. Extension, stage, score and reliability

Keep `score_0_100` (ordinal), `direction`, `stage`, `reliability`, input
windows and forward horizon as separate fields. Missing required evidence
produces an unavailable score and reason, not a fabricated neutral 50.
Feature coverage means measured feature coverage, not a count of connected
vendors; an optional missing perp feed does not automatically remove F1-F5.

For this prospective candidate retain the proposal's extension definition:

```text
E = abs(r_15m) / (sigma_1m * sqrt(15))
  + abs(r_60m) / (sigma_1m * sqrt(60))
```

This is a sum of two overlapping standardized lookbacks, not the number of
standard deviations of one independent return. Use causal midpoint prices
and declare missing extension history unavailable.

**`EXTENDED` is a hard exclusion from early-warning eligibility**, before
percentile ranking. For the candidate, `E > 3.5`, or an absolute daily move
`>10%` with measured trailing daily USD volume `<$1M`, sets `EXTENDED`. Missing
extension/liquidity data must not be treated as proof of eligibility. Stage
precedence is `EXTENDED`, then `FADING/ABSORBED`, then `CONFIRMED`, then
`IGNITING`; otherwise stage is unclassified. `E == 3.5` is not extended
by the E gate. Only complete-data `IGNITING` / `CONFIRMED` candidates enter
the early board, in separate UP/DOWN cohorts. Extended/fading rows may be
retained in shadow diagnostics or a separate risk-context view.

The original soft damper `exp(-max(0,E-3)^2/8)` retains 60.7% at E=5 and
32.5% at E=6 and cannot ensure exclusion. Dividing by 2 would retain 13.5%
and 1.1%; that remains a different hypothesis. The hard stage gate is the
chosen policy here. Do not infer the AURORA mockup's score of 18 from either
formula, or add another penalty/threshold search to this pilot.

Exact stage thresholds other than the extension/activity gates must be
frozen before fitting. Stage names do not establish "<30% of the move
elapsed"; that quantity requires future labels and cannot define live stage.

  a fixed scoring rule and fresh validation period. Neither the sampled
  snapshot gap nor human-friendly UI labels select an optimal timescale.

At each shadow publication retain the contemporaneous eligible universe,
all three rankers (percentage move, current live strength, candidate), raw
features, exclusions, source timestamps, model version, direction, stage
and reliability. Compare on identical complete-data universes/timestamps;
also report each ranker's natural coverage so exclusions remain visible.

Use first Top-K entry, primary K=5 and descriptive K=10, with a 15m per-coin
cooldown shared across the prospective boards. Keep discovery and validation
episodes separate. A cooldown does not make different products, boards or
alerts in the same market episode independent; timing slack can also extend
outcome windows. Do not carry this policy into the historical contract.

Retain lead time to favorable peak, onset-to-publication delay, signed
fraction of move already consumed, false alerts/hour and missed-move rate,

last-trade grade or three observed trades does not certify executable fills.
Use gross outcomes plus declared spread/fee scenarios; never deduct costs

For intervals, bootstrap **paired UTC-day blocks**, retaining all products,
boards and rankers together in each sampled day. Report episode counts,
distinct days, effective blocks and missingness. Seven validation days
provide only seven day blocks; intervals will be fragile. Naive per-alert
standard errors or binomial confidence claims are not acceptable. A boundary
purge prevents cross-split labels; it does not remove within-phase dependence.

Every mockup score, trade count, volume multiple, "historical fade" and
20-35% versus 65-90% move-consumed figure in the pasted proposal is
**illustrative or a hypothesis, not measured Moonwalking performance**.

## Inputs and causality

`TargetEvaluator` accepts one product's strictly ordered, unique receipt-time
snapshots on a 5s grid. Each snapshot has coin and BTC bid/ask, original quote
timestamps, availability time, price-source flags, verified coverage,
deduplicated match count and match-derived USD volume. Quote age must be at
most 10s; both books must be positive and non-crossed. Last-trade fallbacks,
future receipts, unknown coverage and missing grid points are unavailable.
An empty but verified healthy bucket is a known zero, not a collection outage.
The recorder will have to prove these fields; accepting an input object
does not certify its provenance.

Counts/volume at grid time `t` describe `[t-5s,t)`. Forward counts exclude
trades exactly at the anchor: the first forward bucket also needs its
`trade_count_at_bucket_start`. Unknown boundary count means unavailable.
Forward quote states are at times strictly after the anchor. The anchor
itself supplies the starting price, spread and causal baseline.

`Baseline` supplies sigma from the preceding 60 closed 1m log returns,
ending exactly at the anchor's last completed minute, with availability at
or before the anchor. Require at least 60 returns; apply and expose the
0.0015 per-minute floor. Beta is frozen at the anchor with availability
and fallback flags. No rolling future beta/sigma can change the outcome path.
The evaluator checks metadata; candle/beta calculation belongs to the
later recorder/feature implementation.

Pace baselines are medians of 120 prior non-overlapping 30s trade-count and
USD-volume windows, ending exactly 30s before the anchor, available by it.
The current 30s window cannot contribute to its own reference median.
Zero medians cannot produce infinite ratios; at least one positive median
is required. An unavailable pace baseline invalidates onset, while a complete
forward impulse label may still be retained.

## Two separate labels

For direction `d = +1` (up) or `-1` (down), define the favorable residual:

```text
u(t) = d * [log(mid(t)/mid(anchor))
            - beta(anchor) * log(BTC(t)/BTC(anchor))]
```

For each horizon `H = 300s` or `900s`, `verified_forward` requires all of:

- Terminal `u(anchor+H) >= max(3*sigma*sqrt(H/60), 0.015, 3*entry_spread_fraction)`.
- Terminal favorable residual retains at least 60% of the largest favorable
  residual over the horizon. Include zero at the anchor and choose the first
  timestamp when peak values tie. Opposite-direction excursions cannot count
  as favorable merely because their absolute magnitude is large.
- At least three distinct, deduplicated matches strictly after the anchor
  and before the terminal boundary. Valid observed/carried quote coverage is
  required throughout. This is book-presence evidence, not executable fills.

The `0.015` threshold is explicitly in log-return units, approximately 1.5%.
The evaluator also retains adverse residual excursion, terminal return,
retention, first peak time and observed count for failed complete labels.
Rows without a move remain in the output; board entry is not a prerequisite.

`verified_onset` adds the following rules to `verified_forward`:

1. Signed 30s residual velocity divided by `sigma/sqrt(2)` crosses from below
   1 at the previous 5s grid point to at least 1 now. Both use the same causal
   anchor beta/sigma, avoiding a future normalization during evaluation.
2. At least five matches occur in the current 30s window. Its trade-count
   ratio or USD-volume ratio must be **strictly greater than 2** relative to
   its own prior median.
3. Starting from this candidate timestamp, take the first subsequent point
   within 180s with favorable residual at least `1.5*sigma` as the breakout.
4. After the candidate, the favorable residual never falls below zero through
   the full horizon, allowing `1e-12` floating-point tolerance.

The original proposal did not specify the cumulative breakout origin,
no-retrace endpoint or conflict resolution. This v1 fixes those choices:
each activity/velocity crossing supplies the breakout origin, and no-retrace
ends at `onset+H`. These are pilot definitions, not empirically optimal choices.
Onset means an **activity-confirmed threshold crossing**; it is not a claim
to identify the physical first tick of a move. A forward impulse can be real
while this stricter onset definition fails. Report that attrition explicitly.
The same numeric tolerance applies at inclusive/strict comparison boundaries.

## Maturity, event catalog and alert timing

`evaluate(anchor, baseline, direction, H, asof_ts_ms)` returns `pending`
until `anchor+H`, even if a partial path already looks successful. After
maturity, missing or invalid evidence gives `unavailable` and null labels.
`ready` means a complete label; the boolean can still be false. Future rows
after the horizon cannot change it. Endpoint slack is zero; the evaluator
does not interpolate, bridge gaps or select a favorable nearby observation.

`event_catalog` selects the earliest verified onset for each product,
direction and horizon; it suppresses further onsets in `[onset,onset+H)`.
The next onset exactly at the boundary is allowed. This is retrospective
event deduplication, separate from the prospective 15m per-coin alert cooldown
shared across boards. Up/down and 5m/15m catalogs stay separate. They can be
dependent and are not independent statistical observations.

`alert_timing` grades an actual publication timestamp against a verified
event. It uses the preceding grid snapshot only, with quote ages measured
at actual publication, including unaligned publication times:

- `[onset-180s,onset)`: `pre_onset_prediction`.
- At/after onset, at/before peak, with less than half the favorable residual
  peak consumed: `early_detection`.
- Remaining publications through the event end: `late_detection`.
- Outside that association interval: `outside_event_window`.

Detection delay is publication minus onset; lead time is peak minus
publication. Consumed fraction is the signed residual at publication divided
by event peak. It is deliberately not clipped: negative values before onset
and late values remain visible. These are evaluation classes, never live
stages. The future peak is required to calculate them. Alert assignment
across multiple events and operational false-alert/missed-move denominators
still need the frozen universe/alert protocol before fitting.

def load_contract():
    raw = CONTRACT_PATH.read_text(encoding="utf-8").encode("utf-8")
    return json.loads(raw), hashlib.sha256(raw).hexdigest()


@dataclass(frozen=True)
class Sample:
    """State available at ts_ms; counts/volume cover [ts_ms-5000, ts_ms)."""

    product_id: str
    ts_ms: int
    bid: float | None
    ask: float | None
    btc_bid: float | None
    btc_ask: float | None
    quote_ts_ms: int
    btc_quote_ts_ms: int
    available_ts_ms: int
    trade_count: int
    quote_volume_usd: float
    coverage_verified: bool
    price_source: str = "mid"
    btc_price_source: str = "mid"
    trade_count_at_bucket_start: int | None = None

    @property
    def mid(self):
        return (self.bid + self.ask) / 2

    @property
    def btc_mid(self):
        return (self.btc_bid + self.btc_ask) / 2

    @property
    def spread_bps(self):
        return (self.ask - self.bid) / self.mid * 10000


@dataclass(frozen=True)
class Baseline:
    sigma_1m: float
    beta: float
    return_count: int
    end_ts_ms: int
    available_ts_ms: int
    beta_available_ts_ms: int
    beta_fallback: bool
    pace_trade_median_30s: float
    pace_quote_usd_median_30s: float
    pace_window_count: int
    pace_end_ts_ms: int
    pace_available_ts_ms: int


def finite(value):
    return (
        isinstance(value, (float, int))
        and not isinstance(value, bool)
        and math.isfinite(value)
    )


class TargetEvaluator:
    def __init__(self, samples):
        self.cfg, self.contract_sha256 = load_contract()
        self.rows = {}
        self.product_id = None
        previous = None
        for row in samples:
            if (
                not isinstance(row.ts_ms, int)
                or isinstance(row.ts_ms, bool)
                or row.ts_ms % self.cfg["grid_ms"]
            ):
                raise ValueError("sample timestamps must lie on the 5s grid")
            if previous is not None and row.ts_ms <= previous:
                raise ValueError("samples must be strictly increasing and unique")
            if self.product_id is not None and row.product_id != self.product_id:
                raise ValueError("one product per evaluator")
            self.product_id = row.product_id
            self.rows[row.ts_ms] = row
            previous = row.ts_ms
        if not self.rows:
            raise ValueError("samples are required")

    def _quality(self, start, end):
        for ts in range(start, end + 1, self.cfg["grid_ms"]):
            row = self.rows.get(ts)
            if row is None:
                return "missing_grid_point"
            if row.coverage_verified is not True:
                return "unverified_coverage"
            if any(
                type(value) is not int
                for value in (row.available_ts_ms, row.quote_ts_ms, row.btc_quote_ts_ms)
            ):
                return "invalid_timestamp"
            if row.available_ts_ms > ts:
                return "future_receipt"
            if row.price_source != "mid" or row.btc_price_source != "mid":
                return "price_fallback"
            for bid, ask, observed in (
                (row.bid, row.ask, row.quote_ts_ms),
                (row.btc_bid, row.btc_ask, row.btc_quote_ts_ms),
            ):
                if not finite(bid) or not finite(ask) or bid <= 0 or ask < bid:
                    return "invalid_quote"
                if not 0 <= ts - observed <= self.cfg["max_quote_age_ms"]:
                    return "stale_or_future_quote"
            if type(row.trade_count) is not int or row.trade_count < 0:
                return "invalid_trade_count"
            if not finite(row.quote_volume_usd) or row.quote_volume_usd < 0:
                return "invalid_volume"
        return None

    def _baseline_quality(self, baseline, anchor):
        if baseline is None:
            return "missing_baseline"
        if (
            any(
                type(value) is not int
                for value in (
                    baseline.return_count,
                    baseline.end_ts_ms,
                    baseline.available_ts_ms,
                    baseline.beta_available_ts_ms,
                )
            )
            or type(baseline.beta_fallback) is not bool
        ):
            return "invalid_baseline_metadata"
        if (
            not finite(baseline.sigma_1m)
            or baseline.sigma_1m < 0
            or not finite(baseline.beta)
        ):
            return "invalid_baseline"
        if baseline.return_count < self.cfg["minimum_baseline_returns"]:
            return "baseline_warming"
        if baseline.end_ts_ms != anchor // 60000 * 60000:
            return "baseline_window_misaligned"
        if baseline.available_ts_ms > anchor or baseline.beta_available_ts_ms > anchor:
            return "future_baseline"
        return None

    def _residual(self, start, end, beta, direction):
        a, b = self.rows[start], self.rows[end]
        return direction * (
            math.log(b.mid / a.mid) - beta * math.log(b.btc_mid / a.btc_mid)
        )

    def evaluate(self, anchor, baseline, direction, horizon_seconds, asof_ts_ms):
        """Grade every eligible grid anchor, including no-move observations.

        Status 'ready' means a complete label, not a successful impulse.
        All returned outcome/onset fields are evaluation-only.
        """
        if type(horizon_seconds) is not int or type(asof_ts_ms) is not int:
            raise ValueError("horizon and as-of timestamp must be integers")
        if (
            direction not in ("up", "down")
            or horizon_seconds not in self.cfg["outcome_horizons_seconds"]
        ):
            raise ValueError("unsupported direction or horizon")
        if type(anchor) is not int or anchor % self.cfg["grid_ms"]:
            raise ValueError("anchor must lie on the 5s grid")
        sign = 1 if direction == "up" else -1
        end = anchor + horizon_seconds * 1000
        result = dict(
            contract_version=self.cfg["version"],
            contract_sha256=self.contract_sha256,
            evaluation_only=True,
            product_id=self.product_id,
            anchor_ts_ms=anchor,
            horizon_seconds=horizon_seconds,
            direction=direction,
            label_maturity_ts_ms=end,
            status="pending",
            reason="horizon_not_mature",
            verified_forward=None,
            verified_onset=None,
        )
        if asof_ts_ms < end:
            return result
        reason = self._baseline_quality(baseline, anchor) or self._quality(anchor, end)
        if reason:
            return {**result, "status": "unavailable", "reason": reason}
        boundary_count = self.rows[
            anchor + self.cfg["grid_ms"]
        ].trade_count_at_bucket_start
        if (
            type(boundary_count) is not int
            or not 0
            <= boundary_count
            <= self.rows[anchor + self.cfg["grid_ms"]].trade_count
        ):
            return {
                **result,
                "status": "unavailable",
                "reason": "unknown_boundary_trade_count",
            }
        sigma = max(baseline.sigma_1m, self.cfg["sigma_floor_1m"])
        path = [
            (ts, self._residual(anchor, ts, baseline.beta, sign))
            for ts in range(anchor, end + 1, self.cfg["grid_ms"])
        ]
        peak_ts, peak = max(path, key=lambda pair: pair[1])  # first tie wins
        terminal = path[-1][1]
        adverse = min(value for _, value in path)
        retention = terminal / peak if peak > 0 else None
        first, last = self.rows[anchor], self.rows[end]
        rules = self.cfg["impulse"]
        threshold = max(
            rules["terminal_sigma_multiple"] * sigma * math.sqrt(horizon_seconds / 60),
            rules["minimum_terminal_log_return"],
            rules["entry_spread_multiple"] * first.spread_bps / 10000,
        )
        trades = sum(self.rows[ts].trade_count for ts, _ in path[1:]) - boundary_count
        tolerance = self.cfg["comparison_tolerance"]
        verified = (
            terminal + tolerance >= threshold
            and retention is not None
            and retention + tolerance >= rules["minimum_peak_retention"]
            and trades >= rules["minimum_forward_matches"]
        )
        gross_bps = sign * (last.mid / first.mid - 1) * 10000
        spread_cost = (first.spread_bps + last.spread_bps) / 2
        result.update(
            status="ready",
            reason=None,
            verified_forward=verified,
            sigma_1m=sigma,
            sigma_floor_applied=baseline.sigma_1m < sigma,
            beta=baseline.beta,
            beta_fallback=baseline.beta_fallback,
            terminal_residual_log=terminal,
            required_terminal_log=threshold,
            peak_residual_log=peak,
            peak_ts_ms=peak_ts,
            adverse_residual_log=adverse,
            retention=retention,
            forward_trade_count=trades,
            gross_coin_return_bps=gross_bps,
            cost_scenarios=[
                dict(
                    fee_bps_per_side=fee,
                    net_coin_return_bps=gross_bps - spread_cost - 2 * fee,
                )
                for fee in self.cfg["costs"]["fee_bps_per_side_scenarios"]
            ],
        )
        onset = self.cfg["onset"]
        velocity_ms = onset["velocity_window_seconds"] * 1000
        step = self.cfg["grid_ms"]
        reason = self._quality(anchor - velocity_ms - step, anchor)
        if any(
            type(value) is not int
            for value in (
                baseline.pace_window_count,
                baseline.pace_end_ts_ms,
                baseline.pace_available_ts_ms,
            )
        ):
            return {
                **result,
                "onset_status": "unavailable",
                "onset_reason": "invalid_pace_metadata",
            }
        if baseline.pace_window_count < onset["minimum_prior_pace_windows"]:
            reason = reason or "pace_warming"
        if (
            baseline.pace_end_ts_ms != anchor - velocity_ms
            or baseline.pace_available_ts_ms > anchor
        ):
            reason = reason or "future_pace_baseline"
        medians = (baseline.pace_trade_median_30s, baseline.pace_quote_usd_median_30s)
        if not all(finite(value) and value >= 0 for value in medians) or not any(
            value > 0 for value in medians
        ):
            reason = reason or "pace_unavailable"
        if reason:
            return {**result, "onset_status": "unavailable", "onset_reason": reason}
        current_velocity = self._residual(
            anchor - velocity_ms, anchor, baseline.beta, sign
        ) / (sigma / math.sqrt(2))
        previous_velocity = self._residual(
            anchor - velocity_ms - step, anchor - step, baseline.beta, sign
        ) / (sigma / math.sqrt(2))
        recent = [
            self.rows[ts] for ts in range(anchor - velocity_ms + step, anchor + 1, step)
        ]
        recent_trades = sum(row.trade_count for row in recent)
        recent_volume = sum(row.quote_volume_usd for row in recent)
        pace = max(
            (
                value / median
                for value, median in zip((recent_trades, recent_volume), medians)
                if median > 0
            ),
            default=0,
        )
        candidate = (
            previous_velocity < onset["velocity_crossing_sigma"] - tolerance
            and current_velocity + tolerance >= onset["velocity_crossing_sigma"]
            and recent_trades >= onset["minimum_matches_30s"]
            and pace > onset["pace_multiple_strictly_greater_than"] + tolerance
        )
        breakout_ts = next(
            (
                ts
                for ts, value in path[1:]
                if ts <= anchor + onset["breakout_deadline_seconds"] * 1000
                and value + tolerance >= onset["breakout_sigma"] * sigma
            ),
            None,
        )
        no_retrace = adverse >= -onset["no_retrace_tolerance_log"]
        result.update(
            onset_status="ready",
            onset_reason=None,
            onset_candidate=candidate,
            previous_velocity_sigma=previous_velocity,
            velocity_sigma=current_velocity,
            pace_multiple=pace,
            recent_trade_count=recent_trades,
            breakout_ts_ms=breakout_ts,
            no_retrace=no_retrace,
            verified_onset=bool(
                candidate and verified and breakout_ts is not None and no_retrace
            ),
        )
        return result

    def alert_timing(self, label, publish_ts_ms):
        """Retrospective event association; never a live stage or input."""
        if type(publish_ts_ms) is not int:
            raise ValueError("publication timestamp must be an integer")
        if (
            label.get("contract_sha256") != self.contract_sha256
            or label.get("product_id") != self.product_id
            or not label.get("verified_onset")
        ):
            raise ValueError(
                "a verified onset from this contract and product is required"
            )
        anchor = label["anchor_ts_ms"]
        rules = self.cfg["events"]
        if (
            not anchor - rules["prediction_lead_limit_seconds"] * 1000
            <= publish_ts_ms
            <= label["label_maturity_ts_ms"]
        ):
            return dict(evaluation_only=True, timing="outside_event_window")
        # Backward as-of lookup only. Never use the next grid point at publication.
        ts = publish_ts_ms // self.cfg["grid_ms"] * self.cfg["grid_ms"]
        reason = self._quality(ts, ts)
        if reason:
            return dict(evaluation_only=True, timing="unavailable", reason=reason)
        row = self.rows[ts]
        if (
            max(publish_ts_ms - row.quote_ts_ms, publish_ts_ms - row.btc_quote_ts_ms)
            > self.cfg["max_quote_age_ms"]
        ):
            return dict(
                evaluation_only=True, timing="unavailable", reason="stale_alert_quote"
            )
        sign = 1 if label["direction"] == "up" else -1
        consumed = (
            self._residual(anchor, ts, label["beta"], sign) / label["peak_residual_log"]
        )
        timing = (
            "pre_onset_prediction"
            if publish_ts_ms < anchor
            else (
                "early_detection"
                if publish_ts_ms <= label["peak_ts_ms"]
                and consumed
                < rules["early_detection_consumed_fraction_strictly_below"]
                - self.cfg["comparison_tolerance"]
                else "late_detection"
            )
        )
        return dict(
            evaluation_only=True,
            timing=timing,
            detection_delay_seconds=(publish_ts_ms - anchor) / 1000,
            lead_to_peak_seconds=(label["peak_ts_ms"] - publish_ts_ms) / 1000,
            consumed_fraction=consumed,
            price_snapshot_ts_ms=ts,
        )


def event_catalog(labels):
    """Earliest verified event owns [onset,onset+H), per product/direction/H.

    This retrospective deduplication is separate from the live 15m per-coin
    alert cooldown. Unverified/pending rows never suppress another event.
    """
    labels = list(labels)
    selected, ends = [], {}
    hashes = {row["contract_sha256"] for row in labels}
    if len(hashes) > 1:
        raise ValueError("cannot mix target contracts")
    for row in sorted(
        labels,
        key=lambda row: (
            row["anchor_ts_ms"],
            row["product_id"],
            row["direction"],
            row["horizon_seconds"],
        ),
    ):
        key = row["product_id"], row["direction"], row["horizon_seconds"]
        if row.get("verified_onset") and row["anchor_ts_ms"] >= ends.get(
            key, -math.inf
        ):
            selected.append(row)
            ends[key] = row["label_maturity_ts_ms"]
    return selected

):

    portable = tmp_path / "contract.json"
    portable.write_bytes(
        target.CONTRACT_PATH.read_text(encoding="utf-8")
